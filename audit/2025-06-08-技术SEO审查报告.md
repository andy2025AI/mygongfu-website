## 🔴 P0 — 必须立即修复（2项）

### P0-1：所有路由返回200 OK，没有真正的404页面

**问题**：访问 `https://mygongfu.com/nonexistent-page` 返回 **HTTP 200**，内容是 `index.html`。这是 Nginx `try_files` 的副作用——所有不存在的路径都被SPA路由接管。

**影响**：
- 搜索引擎无法识别死链，可能索引大量无效URL
- Google Search Console 中不会报告404错误
- 用户体验差：访问错误URL看到的是首页而非错误提示
- 如果用户分享错误链接，接收者不知道链接已失效

**修复**：
```nginx
# 方案A：Nginx层面拦截已知不存在的路径（推荐）
# 在 try_files 前添加精确的 location 匹配
location ~ ^/(about|geo|fde|pufeng|articles|methods)/?$ {
    try_files $uri /index.html;
    # 这些是真实路由，返回200
}

# 其他路径使用自定义404
error_page 404 /404.html;
location = /404.html {
    root /var/www/mygongfu;
    internal;
}

# 方案B：React Router层面处理（需前端配合）
# 在React中配置 catch-all 路由返回404状态
# 但Nginx仍会返回200，需要SSR支持
```

**推荐**：创建 `/var/www/mygongfu/404.html`，在 nginx 中为主路由添加白名单location，其余返回404。

### P0-2：CSP中 `unsafe-inline` 削弱了安全防护

**问题**：CSP 策略包含 `script-src 'self' 'unsafe-inline'` 和 `style-src 'self' 'unsafe-inline'`，允许内联脚本和样式，这实际上消除了CSP防范XSS的核心能力。

当前CSP：
```
default-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; 
font-src 'self'; script-src 'self' 'unsafe-inline';
```

**影响**：
- 任何注入的内联 `<script>` 标签都能执行
- CSP 形同虚设，无法防御XSS攻击
- 不符合现代安全最佳实践

**修复**：
```nginx
# 方案A：使用 nonce（推荐，需前端配合）
add_header Content-Security-Policy "default-src 'self'; 
  script-src 'self' 'nonce-$request_id'; 
  style-src 'self' 'unsafe-inline'; 
  img-src 'self' data: https:; 
  font-src 'self'; 
  connect-src 'self' https:;" always;

# 方案B：使用 hash（不依赖服务端）
# 在Vite构建后获取打包后的JS hash，配置到CSP中

# 方案C：最小化修复（如果无法去inline）
# 至少添加 frame-ancestors 和 base-uri
add_header Content-Security-Policy "default-src 'self'; 
  script-src 'self' 'unsafe-inline'; 
  style-src 'self' 'unsafe-inline'; 
  img-src 'self' data: https:; 
  font-src 'self'; 
  connect-src 'self' https:; 
  frame-ancestors 'none'; 
  base-uri 'self'; 
  form-action 'self';" always;
```

**注意**：`unsafe-inline` 可能是因为Tailwind CSS和React内联样式需要。短期可用方案C添加更多指令，长期应迁移到nonce方案。

## 🟡 P1 — 重要，建议2周内修复（6项）

### P1-1：纯客户端渲染SPA，无SSR/Prerender

**问题**：网站是完全客户端渲染的React SPA。`web_extract` 工具无法获取任何内容（返回空），Googlebot收到的是只有loading shell的HTML。

虽然Google宣称能渲染JS，但：
- JS渲染有延迟队列（可能数天到数周）
- 渲染预算有限，大型站点可能部分页面不被渲染
- 社交媒体爬虫（Twitter Card、微信）不执行JS
- 初次有意义的绘制依赖JS下载+执行

**当前HTML内容**（Googlebot视角）：
```html
<body>
  <div id="root">
    <div class="loading-shell">朴风 Pu Feng（loading...）</div>
  </div>
</body>
```

**好消息**：`<head>` 中的 meta/OG/JSON-LD 是静态的，搜索引擎可以看到title和description。但 sub-page 的 meta 信息（about/geo/fde等）在JS渲染后才出现，爬虫看不到。

**修复**：
```typescript
// 方案A：Vite SSR（推荐，React Router 7 原生支持）
// vite.config.ts
export default defineConfig({
  plugins: [react()],
  ssr: {
    noExternal: ['react-router-dom'],
  },
})

// 方案B：静态生成子页面HTML（轻量方案）
// 为 /about/, /geo/, /fde/, /pufeng/ 等主路由预渲染HTML
// 使用 vite-plugin-ssr 或 react-snap

// 方案C：Prerender.io / Rendertron 等中间件
// 在Nginx层为爬虫UA返回预渲染HTML
```

**优先级说明**：排名P1而非P0是因为当前 `<head>` 中的meta标签已经覆盖了首页SEO基础。

### P1-2：缺少 Cross-Origin 隔离安全头

**问题**：缺少以下现代安全头：

| 缺失头部 | 作用 |
|:---|:---|
| `Cross-Origin-Opener-Policy` | 防止跨域窗口交互攻击（如Spectre） |
| `Cross-Origin-Resource-Policy` | 控制哪些源可以加载资源 |
| `Cross-Origin-Embedder-Policy` | 控制跨域资源嵌入 |

**修复**：
```nginx
# 添加到 nginx server 块
add_header Cross-Origin-Opener-Policy "same-origin" always;
add_header Cross-Origin-Resource-Policy "same-origin" always;
# COEP 可选，如不需要 SharedArrayBuffer 可不加
# add_header Cross-Origin-Embedder-Policy "require-corp" always;
```

**风险评估**：如果是纯静态站点无第三方资源嵌入，安全添加。如有第三方iframe/脚本需测试。

### P1-3：资源缓存max-age与配置不一致

**问题**：nginx 配置文件指定 `expires 1y`，但实际响应显示 `max-age=2592000`（30天）。

| 资源 | 配置预期 | 实际值 | 实际过期 |
|:---|:---|:---|:---|
| `/assets/index-D5_v6eRU.js` | 1年 | 30天 | 2026-07-08 |
| `/assets/index-BWuUePoP.css` | 1年 | 30天 | 2026-07-08 |
| `/favicon.svg` | 未指定 | 30天 | 2026-07-08 |

**可能原因**：
- 部署的配置与源配置不同步
- CDN/反向代理层覆盖了响应头
- nginx 的 `expires` 指令被其他配置覆盖

**修复**：
```bash
# 1. 检查实际部署的配置
ssh server "cat /etc/nginx/sites-enabled/mygongfu.conf | grep -A5 'location /assets'"

# 2. 确认配置正确
# /assets/ 块的 expires 应该是 "1y" 而非 "30d"

# 3. 如果使用CDN，检查CDN的缓存规则是否覆盖了源站
```

### P1-4：缺少资源预加载提示

**问题**：HTML `<head>` 中没有 `<link rel="preload">`、`<link rel="modulepreload">` 或 `<link rel="preconnect">` 标签。

Vite 生成了 `type="module"` 的脚本，但没有 modulepreload 提示。浏览器需要先下载HTML、解析、发现script标签后才开始下载JS。这增加了首屏渲染的延迟。

**修复**（Vite配置）：
```html
<!-- 在 index.html 的 <head> 中添加 -->
<link rel="modulepreload" href="/assets/index-D5_v6eRU.js">
<link rel="preload" href="/assets/index-BWuUePoP.css" as="style">
<!-- 如果有外部资源 -->
<link rel="preconnect" href="https://fonts.googleapis.com">
```

或在 vite.config.ts 中：
```typescript
export default defineConfig({
  build: {
    modulePreload: {
      polyfill: true, // 已包含polyfill，但需确保polyfill生效
      resolveDependencies: (filename, deps) => [filename],
    },
  },
})
```

### P1-5：HSTS 配置来源不明

**问题**：HTTP响应中包含`Strict-Transport-Security: max-age=31536000`，但当前nginx配置文件中没有 `add_header Strict-Transport-Security`。

**可能位置**：
- nginx 全局配置（`/etc/nginx/nginx.conf`）
- CDN 层（Cloudflare等）
- 部署的配置与源文件不同（更可能是这个）

**修复**：
```nginx
# 显式添加到 server 块中，确保可控
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;
```

### P1-6：JS Bundle 体积大（~587KB 未压缩 / ~116KB gzip）

**问题**：单个JS文件包含了所有应用代码，无代码分割。

| 依赖 | 估算大小 | 
|:---|:---|
| React + ReactDOM | ~130KB |
| React Router 7 | ~30KB |
| Lucide React (图标库) | 可能较大 |
| Tailwind CSS (通过JS) | ~30KB |
| Zustand | ~5KB |
| 应用代码 | 未知 |

**修复**：
```typescript
// vite.config.ts - 添加代码分割
export default defineConfig({
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          'react-vendor': ['react', 'react-dom'],
          'router': ['react-router-dom'],
          'ui': ['lucide-react'],
        },
      },
    },
    // 提高chunk大小警告阈值
    chunkSizeWarningLimit: 1000,
  },
})
```

## 🟢 P2 — 建议优化（5项）

### P2-1：Sitemap 缺少元数据

**问题**：sitemap.xml 中所有URL只有 `<loc>`，缺少 `<lastmod>`、`<changefreq>`、`<priority>`。

```xml
<!-- 当前 -->
<url><loc>https://mygongfu.com/</loc></url>

<!-- 建议 -->
<url>
  <loc>https://mygongfu.com/</loc>
  <lastmod>2026-06-08</lastmod>
  <changefreq>weekly</changefreq>
  <priority>1.0</priority>
</url>
```

### P2-2：SSL 证书有效期短（90天）

ZeroSSL ECC DV证书有效期：2026-05-13 ~ 2026-08-11（90天）。

**建议**：设置自动续期cron（certbot或acme.sh），否则8月11日后网站将出现证书错误。

```bash
# certbot 自动续期
0 3 * * * certbot renew --quiet --deploy-hook "systemctl reload nginx"

# 或检查已有的定时任务
crontab -l | grep certbot
```

---

### P2-3：可能存在开发工具泄漏到生产环境

**发现**：`vite.config.ts` 配置了 `babel-plugin-react-dev-locator`。虽然该插件通常在开发模式下工作，且在production build中应该被tree-shaking掉，但建议确认生产构建不包含任何开发工具。

```bash
# 检查生产JS中是否包含开发工具引用
grep -c "react-dev-locator" dist/assets/*.js
```
